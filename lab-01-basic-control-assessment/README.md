# 🧪 Lab 01 — Basic Control Assessment: Screen Lock Control

## 📌 Overview

This introductory GRC lab demonstrates the basic process of evaluating a security control against a defined requirement and using evidence to determine whether the control is operating effectively.

The exercise uses a simulated workstation screen-lock scenario to practice translating a security requirement into a testable control assessment.

> **Lab Type:** Simulated GRC Control Assessment  
> **Control Area:** Access Control / Workstation Security  
> **Assessment Focus:** Operating Effectiveness

---

## 🎯 Objective

Evaluate an automatic workstation screen-lock control to determine whether available evidence demonstrates that the control is operating in accordance with the organization's defined requirement.

The assessment follows the basic workflow:

**Requirement → Control → Objective → Test → Evidence → Result → Conclusion**

---

## 🏢 Scenario

A fictional organization requires employee workstations to automatically lock after a defined period of inactivity.

The automatic screen-lock control is intended to reduce the risk of unauthorized access when an authorized user leaves a workstation unattended.

During the simulated assessment, the workstation did not automatically lock within the organization's required inactivity period.

Available configuration information also did not demonstrate that the required automatic-lock setting had been properly implemented.

---

## 🔎 Assessment Approach

The assessment consisted of:

1. Identifying the applicable requirement.
2. Identifying the security control.
3. Determining the control objective.
4. Determining how the control could be tested.
5. Reviewing the simulated evidence.
6. Comparing the observed condition against the expected condition.
7. Determining whether the control was operating effectively.
8. Documenting the assessment conclusion.

---

## 📋 Assessment Summary

| Assessment Area | Result |
|---|---|
| **Control** | Automatic Workstation Screen Lock |
| **Control Objective** | Reduce unauthorized access to unattended workstations |
| **Expected Condition** | Workstation automatically locks within the organization's required inactivity period |
| **Observed Condition** | Workstation did not automatically lock within the required period |
| **Test Result** | Failed |
| **Operating Effectiveness** | Not Effective |
| **Retesting Required** | Yes |

---

## ⚠️ Risk Identified

An unattended workstation that remains accessible longer than permitted may increase the opportunity for unauthorized access to organizational systems or information.

---

## 🔧 Recommended Remediation

Review and configure the workstation's automatic screen-lock settings to meet the organization's established inactivity requirement.

After remediation, the control should be retested to verify that the configuration has been implemented correctly and that the workstation automatically locks as required.

## 💡 Key Takeaway

A security control should not be considered effective simply because a policy, setting, or technology exists.

The assessor must determine whether sufficient evidence demonstrates that the control is **implemented and operating as required**.
